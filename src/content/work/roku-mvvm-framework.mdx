## The problem

Every Roku app we built needed the same plumbing: moving between pages, keeping track of which element has focus when the user presses the remote, and loading data from APIs without freezing the screen. Each project solved it slightly differently, which made apps slower to build and harder to hand over between developers.

## What I built

I designed and built a reusable **MVVM framework** for Roku SceneGraph. It separates what the user sees (views) from the data and logic behind them (view models), and gives every app the same building blocks for:

- **Page navigation:** a consistent way to open, close and go back between screens.
- **Focus handling:** predictable remote-control focus across rows, grids and dialogs.
- **API data loading:** a standard pattern for fetching and preparing data off the main thread.

## The outcome

- Page data-loading time dropped by **30–40%**.
- Code typing time fell by **50%**: new apps and screens were faster to build because the hard parts were already solved.
- The framework became the foundation for later Roku apps, including **Crackle** and **BBC**.
